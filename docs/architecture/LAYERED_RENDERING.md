# Layered rendering (#77)
## Comparative audit
RimWorld (Verse-era through 1.6) separates Pawn path following, draw position and drawing; its node-based pawn rendering and dynamic phases separate preparation from drawing. Version 1.6 introduces variable tick rate and batched parallel pathfinding. Sources: https://github.com/Chillu1/RimWorldDecompiledWeb/blob/master/Verse.AI/Pawn_PathFollower.cs ; https://github.com/Chillu1/RimWorldDecompiled/blob/master/Verse/Pawn.cs ; https://rimworldwiki.com/wiki/User:Harakoni ; https://rimworldwiki.com/wiki/Version/1.6.4518 . Independent implementation, no copied game source. Not a claim about Waylith 1.7 internals.
Oturo main 0d1bd4e: 4/8/16 nominal TPS; 62.5ms scheduler quantum; sync persistence before publication; WS revisions; TickPlayback buffer 32 and nominal delay 250/speed. Canvas redraws terrain cells and sorts logical positions every frame; items, occlusion, UI and sprites already exist.
## Increment
Default layered adapter composes existing TickPlayback with TerrainCache (8×8 chunks, 64-entry LRU, raster 42px/cell, ~28MiB RGBA upper bound excluding overhead at default tile size), and visual-order plan. Terrain is procedural and immutable; keys include map dimensions, tile, detail. No map-dependent terrain state currently. If terrain becomes mutable, add chunk revision invalidation before caching. Buildings remain dynamically ordered to preserve occlusion; items/planting/brush retain existing behavior. Conservative culling by footprint plus 2 cells. Legacy and tick rollback: ?renderer=legacy and ?renderer=tick; default layered. No changes to engine, protocol, persistence, sprites or gameplay. Canvas cache not equivalent to Unity mesh batching.
## Remaining differences
RimWorld local draw uses current movement progress; Oturo interpolates confirmed snapshots, has network delay and potential stop/start between cell steps. No extrapolation, no path prediction. Future authoritative movement segment contract (from/to, start/end logical time, progress, cancellation, collision ownership) belongs to #23/#59; migration must preserve duration, costs, save and determinism. No TPS increase in this increment. Static building cache, spatial index, animation graph and GPU batching remain future profiling-driven work.
