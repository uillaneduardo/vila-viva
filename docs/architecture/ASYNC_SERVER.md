# Experimental async HTTP composition (#77)
Opt-in OTURO_ASYNC_PERSISTENCE=1 with data directory. Default stays synchronous. Bootstrap completes before worker startup; subsequent disk reads/writes use worker RPC. HTTP POST/disk reads take single-flight gate; busy returns 503, ordinary world reads see last confirmed state. Tick drafts publish after durable ack. Failed commits pause simulation. New-world bootstrap writes a single initial action batch with the new timeline; existing sync bootstrap unchanged. No TPS increase. Known limitations: busy pulses skipped; no automatic retry, explicit recovery/restart on failed commit; request body currently holds gate; shutdown needs further fault-injection validation; no full power-loss guarantee. Tests cover opt-in HTTP commands, named save, world replacement, load, export. Do not enable in production before concurrency, populated-world and crash benchmarks. Worker is exclusive by convention, not OS lock. The prior AsyncTickDriver and CommittedWorld remain independently testable prototypes; HTTP composition uses equivalent gate/draft semantics rather than instantiating them to preserve existing server routes.

## Lifecycle hardening
Parse request bodies before acquiring the mutation gate, return Retry-After on busy, pause on failed named save, hide synchronous store handle in async mode, and provide idempotent awaitable shutdown after server close. Tests wait for worker termination before deleting data and verify recovery after acknowledged command. Shutdown must be called after HTTP close; not a full SIGTERM/crash guarantee. No activation or TPS changes.
