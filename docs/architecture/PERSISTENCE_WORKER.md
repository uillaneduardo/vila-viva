# Persistence worker prototype (#77/#23/#27)
Audit: active checkpoint is written every tick; accepted actions alone do not reconstruct passive state, RNG or ordering. The existing store appends and fsyncs an action batch, copies previous checkpoint, writes and fsyncs temporary checkpoint, then renames. Existing implementation does not fsync directory entries and must not be described as power-loss proof. The worker prototype moves the same store operations into a Node worker, acknowledges only after commit returns, owns its directory exclusively, captures immutable input and permits one outstanding operation. Busy rejects; failure closes the write path. No changes to disk format. Tests cover checkpoint recovery after worker exit, immutable input, backpressure and fail-closed behavior. This is intentionally not wired to the production composition root: server commands, ticks, exports, named saves, imports and timeline switches currently use synchronous shared ownership. Enabling requires one serialized authority for all mutations and disk reads, committed-state publication, failure recovery, graceful shutdown, crash injection at journal/checkpoint boundaries, directory durability audit and benchmarks. Never run worker alongside the synchronous store on the same directory. Do not acknowledge uncommitted commands or publish speculative world state. A single outstanding commit may still limit TPS; measure before changing policy. No replay guarantee beyond existing checkpoint semantics.

## Exclusive RPC and committed-state boundary
Worker supports startup recovery, named saves, snapshots and journal reads through the same single-flight RPC. Read failures reject the request without poisoning the writer; write failure requires recovery. CommittedWorld isolates a draft, accepts one mutation at a time, and replaces the visible state only after checkpoint acknowledgement. It is not yet wired into HTTP/timer/WS; named saves and timeline switches need a unified composition transaction and clock handling. No production persistence policy changed. Tests verify visibility before/after acknowledgement, rejection of concurrent mutation, failure isolation and recovery. Directory ownership is a caller contract, not an OS lock.
