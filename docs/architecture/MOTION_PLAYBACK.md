# Motion playback — #77 incremental contract
The engine records from/to/startTick/endTick on accepted movement.move, using the existing charged nextMoveTick. World occupancy still changes immediately, energy/collision/AI/cost remain identical. This is a **confirmed move visual record**, not future reservation or a physical movement controller. Visual arrival may lag logical actions. The optional field is validated in snapshots; old saves remain accepted, no version bump. Existing projection and delta include it without separate network loop. MotionPlayback estimates fractional progress from confirmed tick and local monotonic elapsed time, clamps to one tick ahead, never predicts another cell. Same-tick revisions do not restart phase; pause/death/carried/invalid destination snap to authoritative position. World/epoch resets re-anchor. Speed changes re-anchor and may visibly snap; subsequent work needs continuous clock mapping and explicit cancellation. Legacy entities use TickPlayback fallback. Default motion, ?renderer=layered/tick/legacy for comparison. No TPS, scheduler, persistence or gameplay change. Next gates: real browser benchmark, authoritative reservation/arrival contract, clock separation (#23), durable worker (#27), directional animation. Do not claim full RimWorld parity.
